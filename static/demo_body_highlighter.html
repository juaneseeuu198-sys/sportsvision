✅ UX claramente superior. El body highlighter es más intuitivo que las tarjetas: el usuario ve qué está seleccionando en contexto anatómico real.
✅ Feedback visual inmediato. Ver el músculo iluminarse en el cuerpo reduce errores de selección ("quería pecho, no tríceps").
✅ Mobile-first natural. Dos paneles SVG pequeños tocan bien con el pulgar; las tarjetas actuales a veces quedan muy pequeñas en el grid de 3 columnas.
⚠️ La librería React no es rentable aquí. El proyecto es Django puro — adoptar React solo para este paso implica añadir npm, webpack/vite, un bundle y sincronizar el estado con los checkboxes del form. La deuda técnica supera el beneficio.
⚠️ Los slugs no encajan 1:1. react-body-highlighter usa nombres en inglés (chest, glutes, quadriceps…). Habría que mantener un mapa de traducción y verificar que los 11 grupos del modelo tengan equivalente exacto en la librería.
❌ Dependencia externa de nicho. El paquete tiene mantenimiento irregular. Si se abandona o rompe con una versión de React, habría que reescribirlo de todas formas.
Recomendación: implementar el body highlighter tal como muestra este demo — SVG puro + vanilla JS, integrado directamente en paso2_musculos.html. Se obtiene el 95% de la UX de la librería React con cero dependencias externas, cero build step, y mantenimiento total. El demo de arriba es funcional: pruébalo ahora mismo.
