================================================================================
                     SPORTSVISION — RESUMEN COMPLETO DEL PROYECTO
================================================================================

DESCRIPCION GENERAL
-------------------
SportsVision es una plataforma full-stack de fitness y nutricion con:
  - Backend:  Django (Python) con templates HTML
  - Frontend: Django templates + JavaScript (responsive, PWA)
  - Mobile:   App Android con WebView embebido
  - Base de datos: PostgreSQL (Railway) / SQLite en memoria (build-time)
  - Despliegue: Railway (https://web-production-f0f4b.up.railway.app)

Version actual: 1.1 (versionCode 2)

SPLITS CONFIGURABLES
--------------------
  3 dias: Empuje | Jalon | Piernas
  4 dias: Superior A | Inferior A | Superior B | Inferior B
  5 dias: Pecho&Triceps | Espalda&Biceps | Piernas | Hombros&Core | Full Body
  6 dias: Empuje A/B | Jalon A/B | Piernas A/B

ADAPTACION POR LIMITACIONES DE SALUD
--------------------------------------
  - Lesion de rodilla: excluye sentadillas, agrega movilidad
  - Embarazo:          evita abdomen, prioriza movilidad y ejercicios bajos
  - Movilidad reducida: split adaptado con menos carga articular
  - El generador usa _adaptar_grupos(), _get_split_adaptado() y _qs_ejercicios()

8. FLUJOS PRINCIPALES
================================================================================

REGISTRO (3 PASOS)
------------------
  Paso 1: Usuario ingresa email
          -> Sistema genera OTP de 6 digitos
          -> Envia via Brevo API (email)
          -> Guarda EmailPreVerification (expira 15 min)

  Paso 2: Usuario ingresa OTP
          -> Valida codigo y expiracion
          -> Marca email como pre-verificado en sesion

  Paso 3: Usuario completa datos (usuario, password, nombre, etc.)
          -> Crea User + UserProfile
          -> Opcionalmente genera plan inicial de rutinas
          -> Redirige al dashboard

LOGIN CON GOOGLE (OAuth2)
--------------------------
  1. GET /usuarios/auth/google/ -> genera state anti-CSRF, redirige a Google
  2. Google Callback:
     a. Valida state
     b. Intercambia code por access_token
     c. Obtiene datos de Google (email, nombre, foto)
     d. Crea o actualiza usuario
     e. Si nuevo usuario: redirige a completar_perfil_google
     f. Si usuario existente: login directo, redirige a dashboard

  Flujo Mobile (desde WebView Android):
     1. WebView abre Custom Tabs para Google
     2. Callback genera MobileLoginToken (UUID, expira 120s)
     3. Retorna HTML con intent://sportsvision://auth?token=UUID
     4. Android intercepta deep link
     5. GET /usuarios/auth/mobile/?token=UUID -> valida token -> login

CREAR RUTINA
------------
  Paso 1: Selecciona equipos disponibles
  Paso 2: Selecciona grupos musculares objetivo
  Paso 3: Elige ejercicios especificos (con sugeridos recientes)
          Opcional: asigna a dia de la semana -> crea PlanDia

ENTRENAMIENTO ACTIVO
--------------------
  1. Inicia desde rutina -> crea objeto Entrenamiento
  2. Por cada ejercicio:
     - Muestra historial de series previas
     - Formulario para registrar: reps, peso, tiempo
     - POST guardar_serie -> crea SerieEntrenamiento
     - Calcula progreso (%)
  3. Terminar -> marca Entrenamiento como completado
  4. Resumen: peso total levantado, duracion, musculos trabajados (emojis)

PLAN SEMANAL AUTOMATICO
-----------------------
  - Usuario define: nivel, dias disponibles, equipos
  - Sistema selecciona split (3/4/5/6 dias)
  - Adapta segun limitaciones (lesiones, embarazo, etc.)
  - Genera rutinas con ejercicios filtrados por nivel y equipo
  - Asigna a dias de la semana en PlanDia

SISTEMA DE PRIVACIDAD PROFESIONAL
----------------------------------
  1. Usuario solicita ser profesional (Admin Pro revisa y aprueba)
  2. Profesional obtiene codigo_pro unico
  3. Cliente ingresa codigo -> crea RelacionProfesional (activa)
  4. Cliente controla permisos granulares:
       ver_datos_basicos | ver_entrenamientos | ver_mediciones |
       ver_nutricion | ver_salud
  5. Profesional solo accede a datos con permiso explicitamente concedido
  6. Cliente puede revocar la relacion en cualquier momento

  1. Email + Password (backend propio)

  3. Mobile Token (UUID, un solo uso, expira 2 min)
  4. Email OTP en registro (6 digitos, expira 15 min)

ROLES
  usuario    -> acceso a su perfil, rutinas, herramientas, progreso
  profesional-> + dashboard de clientes, ver datos segun permisos
  admin_pro  -> + gestion de solicitudes, ver cualquier usuario,
                  crear rutinas, banear, sancionar

================================================================================
10. SEGURIDAD
================================================================================

  - Contrasenas:    hashing Django (PBKDF2)
  - Avatares:       base64 en BD (evita filesystem sync entre instancias)
  - Token OAuth:    intercambia, no persiste (sesion Django)
  - Mobile token:   UUID, un solo uso, expira 120s
  - Email OTP:      6 digitos, expira 15 min
  - State CSRF:     anti-replay con sufijo ':mobile' para distinguir origen
  - Datos sensibles (telefono/direccion): requieren verificar password del admin
  - Baneo temporal: SuspensionMiddleware revisa suspendido_hasta en cada request
  - Cookies:        SameSite=None + Secure=True para compatibilidad WebView

USO DE PYTHON EN EL CODIGO
----------------------------
  ORM Django:
    - Modelos como clases Python (models.Model)
    - Migraciones generadas automaticamente con makemigrations
    - Queries con .filter(), .annotate(), .select_related(), .prefetch_related()
    - JSONField nativo (Python dict/list directo en BD)

  Vistas (views.py):
    - Funciones Python decoradas con @login_required, @csrf_exempt
    - Logica de negocio: calculos de TMB/GETD, generacion de splits, etc.
    - Retornan HttpResponse, JsonResponse o render(request, template, context)

  Modulos de la libreria estandar usados:
    - uuid          -> tokens de un solo uso (MobileLoginToken, EmailVerification)
    - base64        -> codificacion de avatares para almacenamiento en BD
    - threading     -> hilo separado para verificar actualizacion del APK (Android)
    - json          -> serializacion/deserializacion de plan_json en PlanNutricional
    - os            -> lectura de variables de entorno en settings.py
    - pathlib.Path  -> rutas de archivos en settings.py (BASE_DIR)
    - datetime      -> calculos de expiracion de tokens

  Management Commands (Python CLI con Django):
    seed_exercises      -> puebla el catalogo de ejercicios en la BD
    setup_admin         -> crea el usuario admin_pro inicial
    compile_messages    -> compila archivos .po de traducciones a .mo
    link_exercise_images-> vincula imagenes estaticas a ejercicios existentes
    slice_muscle_images -> procesa imagenes de grupos musculares

  Middleware personalizado (Python):
    SuspensionMiddleware -> intercepta cada request, verifica si el usuario
                           esta suspendido (suspendido_hasta > now()), redirige
                           con mensaje si corresponde

  Backend de autenticacion personalizado:
    EmailOrUsernameBackend -> clase Python que extiende ModelBackend,
                              permite login con email O nombre de usuario

  Generacion de PDFs con ReportLab:
    - Crea documentos en memoria (BytesIO)
    - Inserta imagenes de ejercicios (Pillow para procesar)
    - Retorna como HttpResponse con Content-Type: application/pdf

  Llamadas HTTP con requests:
    - Brevo API: POST /v3/smtp/email para enviar OTPs
    - Google OAuth: GET /tokeninfo, GET /userinfo
    - Anthropic API: POST /v1/messages para FitBot

DESPLIEGUE EN RAILWAY (railway.toml)
--------------------------------------
  Builder:      NIXPACKS (detecta Python por requirements.txt)

  Build command:
    python manage.py collectstatic --noinput
    -> Copia todos los archivos estaticos a staticfiles/ (WhiteNoise los sirve)

  Start command (secuencial):
    python manage.py migrate           -> aplica migraciones pendientes
    python manage.py seed_exercises    -> asegura ejercicios en BD
    python manage.py setup_admin       -> asegura usuario admin_pro
    python manage.py compile_messages  -> compila traducciones
    gunicorn sportsvision.wsgi --log-file -  -> inicia servidor

  Health check: GET / (timeout 300s)
  Restart policy: ON_FAILURE
