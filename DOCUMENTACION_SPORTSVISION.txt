------------------------------------------------------------------------
2.1 MODELO: UserProfile  (models.py)
------------------------------------------------------------------------
Extiende al User de Django con datos del deportista.
Relación: OneToOne con django.contrib.auth.models.User

Campos:
  user            → ForeignKey al User de Django (relación 1:1)
  edad            → Entero, edad del usuario (años)
  peso            → Float, peso en kg
  altura          → Float, altura en cm
  avatar          → ImageField, foto de perfil (se guarda en media/avatars/)
  genero          → CharField: 'M' Masculino | 'F' Femenino | 'O' Otro
  objetivo        → CharField con opciones:
                      bajar_peso | mantener_peso | ganar_musculo |
                      mejorar_resistencia | mejorar_flexibilidad | rendimiento
  nivel           → CharField: principiante | intermedio | avanzado
  limitaciones    → JSONField (lista Python), condiciones de salud del usuario.
                    Ejemplo: ["asma", "lesion_rodilla"]
                    Opciones disponibles:
                      asma, cardiaco, hipertension, diabetes,
                      lesion_muscular, lesion_rodilla, lesion_espalda,
                      lesion_hombro, articulacion, movilidad_reducida,
                      embarazo, otra
  fecha_registro  → DateTimeField, se guarda automáticamente al crear

2.2 FORMULARIOS  (forms.py)
------------------------------------------------------------------------

EditarUsuarioForm
  → Modelo: User de Django
  → Campos: first_name, last_name, email
  → Uso: Página "Editar Perfil"

EditarPerfilForm
  → Modelo: UserProfile
  → Campos: edad, peso, altura, avatar
  → Uso: Página "Editar Perfil"

RegistroForm (hereda de UserCreationForm)
  → Campos del formulario de 4 pasos:
      Paso 1: username, email, password1, password2
      Paso 2: first_name, edad, peso, altura, genero
      Paso 3: objetivo (cards visuales)
      Paso 4: limitaciones (checkboxes de condiciones de salud)
  → Método save():
      1. Crea el User de Django
      2. Deriva el 'nivel' desde el objetivo:
           ganar_musculo → intermedio
           rendimiento   → avanzado
           resto         → principiante
      3. Crea UserProfile con todos los datos
      4. Guarda la lista de limitaciones como JSON

LoginForm (hereda de AuthenticationForm)
  → Permite login con email O username
  → Backend personalizado: EmailOrUsernameBackend

2.3 VISTAS  (views.py)
------------------------------------------------------------------------

landing(request)
  → GET: muestra la página de inicio pública
  → Si ya está autenticado → redirect al dashboard

auth_choice(request)
  → Muestra la pantalla de elección: Login o Registro

registro(request)
  → GET:  muestra el formulario de registro (4 pasos en JS)
  → POST: valida RegistroForm
           → Si válido: crea usuario, hace login automático
           → Si tiene objetivo: llama a generar_plan_inicial()
             y redirige a plan_semanal con banner de bienvenida
           → Si no tiene objetivo: redirige al dashboard

login_view(request)
  → GET:  muestra formulario de login
  → POST: autentica con EmailOrUsernameBackend
           → Si válido: redirect al dashboard

logout_view(request)
  → Cierra la sesión y redirige al landing

perfil(request)
  → Requiere login (@login_required)
  → Calcula estadísticas del usuario:
      total_entrenamientos → cuenta Entrenamiento.completado=True
      total_rutinas        → cuenta Rutina del usuario
      total_series         → cuenta SerieEntrenamiento del usuario
      kg_levantados        → suma peso*repeticiones de todas las series
  → Calcula IMC: peso / (altura/100)²
  → Pasa historial de entrenamientos recientes (últimos 5)
  → Renderiza: templates/users/perfil.html

editar_perfil(request)
  → GET:  pre-rellena EditarUsuarioForm y EditarPerfilForm
  → POST con 'avatar' en FILES y sin 'first_name':
           → Guarda solo el avatar (flujo rápido desde el modal del perfil)
           → Elimina el avatar anterior antes de guardar el nuevo
  → POST normal: valida ambos formularios y guarda todo
  → Redirect a perfil al guardar

eliminar_avatar(request)
  → Solo acepta POST
  → Elimina el archivo de imagen del storage
  → Pone avatar=None en el perfil
  → Redirect a perfil con mensaje de éxito

------------------------------------------------------------------------

Modal de avatar (al hacer clic en la foto):
  → Muestra la imagen completa (object-fit: contain)
  → Botón "Editar" → abre selector de archivo + cropper
  → Botón "Descargar" → link con atributo download a la URL del avatar
  → Botón "Eliminar" → formulario POST a eliminar_avatar

Editor de recorte (Cropper.js vía CDN):
  → Solo para imágenes NO-GIF (JPG, PNG, WebP)
  → GIFs se suben directamente sin recortar (preserva animación)
  → aspectRatio: 1 (cuadrado → círculo)
  → dragMode: 'move' (arrastra la imagen dentro del marco)
  → Slider de zoom: rango 0-3, mapeado a Math.pow(2, val) → 1× a 8×
  → Preview circular en tiempo real (#crop-preview-circle)
  → "Aplicar": getCroppedCanvas(400×400) → toBlob → DataTransfer → submit

3.3 MODELO: Ejercicio  (models.py)
------------------------------------------------------------------------
El catálogo central de ejercicios (283 ejercicios totales).

Campos:
  nombre           → Nombre del ejercicio
  descripcion      → Qué músculos trabaja y cómo
  instrucciones    → Cómo ejecutarlo correctamente

  equipos          → ManyToMany con Equipo (puede necesitar varios)
  imagen           → ImageField opcional

  nivel            → principiante | intermedio | avanzado
  duracion_minutos → PositiveInteger (nullable).

                     Indica cuántos minutos dura la sección.
                     NULL = ejercicio de fuerza (usa series/reps)
  creado_en        → DateTimeField automático

Ejercicios por grupo (aprox.):
  Piernas: 30  |  Espalda: 27  |  Pecho: 26  |  Hombros: 23
  Abdomen: 21  |  Cardio: 21   |  Core: 21   |  Glúteos: 21
  Movilidad: 21|  Tríceps: 20  |  Antebrazos: 19 | Bíceps: 17
  Pantorrillas: 16

Tiempos de cardio asignados:
  1 min: Sprint en el Lugar
  2 min: High Knees, Bear Crawl, Jump Lunge, Lateral Shuffles, Skipping
  3 min: Jumping Jacks, Box Jumps, Swing con Kettlebell, Speed Skaters
  4 min: Tabata Squat
  5 min: Jump Rope, Kick Boxing en el Aire, Sprints de 20m

------------------------------------------------------------------------
3.4 COMANDO: seed_exercises  (management/commands/seed_exercises.py)
------------------------------------------------------------------------

Uso: python manage.py seed_exercises
     python manage.py seed_exercises --reset

SeedExercise (dataclass):
  nombre, grupo_slug, nivel, equipos (tuple), descripcion,
  instrucciones, duracion_minutos (None por defecto)

Lógica del comando:
  1. Crea los 13 GrupoMuscular con get_or_create
  2. Crea los equipos con get_or_create
  3. Si --reset: elimina todos los ejercicios
  4. Para cada SeedExercise:
       → get_or_create por nombre
       → Si ya existía: actualiza campos vacíos y duracion_minutos
       → Si es nuevo: crea con todos los campos
       → Asigna los equipos con ejercicio.equipos.add()
  5. Reporta cuántos se crearon y cuántos se actualizaron

4.7 ADAPTACIONES POR LIMITACIONES DE SALUD  (views.py)
------------------------------------------------------------------------

_LIM_GRUPOS_EXCLUIDOS:
  Lesión de rodilla    → excluye: piernas, glúteos
  Lesión de hombro     → excluye: hombros
  Movilidad reducida   → excluye: piernas, glúteos, cardio
  Embarazo             → excluye: cardio, abdomen
  Asma                 → excluye: cardio
  Cardíaco             → excluye: cardio

_LIM_GRUPOS_EXTRA (grupos de compensación):
  Lesión de rodilla    → agrega: movilidad, core, antebrazos
  Lesión de espalda    → agrega: movilidad, core
  Lesión de hombro     → agrega: movilidad, core, piernas
  Movilidad reducida   → agrega: movilidad, core, antebrazos, pantorrillas
  Embarazo             → agrega: movilidad, pantorrillas
  Cardíaco/Asma        → agrega: movilidad

_LIM_NOMBRES_EXCLUIDOS (palabras clave en nombres de ejercicios):
  Lesión rodilla → sentadilla, zancada, peso muerto, prensa, nordic...
  Lesión espalda → peso muerto, good morning, rack pull, hiperextensiones...
  Lesión hombro  → press militar, fondos, elevaciones, handstand...
  Asma/Cardíaco  → burpee, sprint, box jump, tabata, thrusters...
  Embarazo       → crunch, sit-up, salto, hollow, dragon flag...

_LIM_NIVEL_MAX (nivel máximo permitido):
  cardíaco/movilidad_reducida/embarazo → principiante
  lesión_muscular → principiante
  resto de lesiones/asma/hipertensión  → intermedio

_SPLITS_ADAPTADOS (splits alternativos para casos severos):
  lesion_rodilla:    3/4/5 días solo tren superior + core + movilidad
  movilidad_reducida: 3/4/5 días solo tren superior
  embarazo:          3/4/5 días movilidad + tren superior suave

4.8 FUNCIONES AUXILIARES  (views.py)
------------------------------------------------------------------------

_adaptar_grupos(grupos_slugs, limitaciones):
  1. Reúne todos los grupos excluidos según las limitaciones
  2. Filtra los grupos originales quitando los excluidos
  3. Agrega grupos de compensación que no estén excluidos
  4. Si quedó vacío, usa ['movilidad', 'core']
  5. Retorna (grupos_adaptados, nombres_a_excluir, nivel_max)

_get_split_adaptado(limitaciones, dias, split_default):
  → Busca en orden: embarazo > movilidad_reducida > lesion_rodilla
  → Si encuentra uno, retorna el split alternativo para ese nº de días
  → Si no, retorna el split estándar

_qs_ejercicios(grupos, nivel, excluir_nombres, equipos_ids):
  → Construye QuerySet: grupo IN grupos AND nivel=nivel
  → Si equipos_ids: filtra también por equipo
  → Excluye ejercicios cuyo nombre contenga las palabras clave
  → Retorna QuerySet

_nivel_ajustado(nivel_base, nivel_max_lim):
  → Retorna el nivel más restrictivo de los dos

_get_limitaciones(user):
  → Retorna user.profile.limitaciones o [] si hay error

4.9 VISTA: generar_plan_inicial(user, objetivo)  (views.py)
------------------------------------------------------------------------
Se llama automáticamente al registrarse con objetivo seleccionado.

Paso a paso:
  1. Obtiene config desde OBJETIVO_CONFIG (días, nivel)
  2. Obtiene las limitaciones del usuario
  3. Elige el split estándar o adaptado según limitaciones
  4. Elimina el plan semanal anterior del usuario
  5. Para cada día de la semana:
       → Si corresponde a una sesión del split:
           a. Adapta los grupos con _adaptar_grupos()
           b. Ajusta el nivel
           c. Construye QuerySet con _qs_ejercicios()
           d. Si quedan < 3 ejercicios, hace fallback a principiante
           e. Crea Rutina con nombre de la sesión
           f. Crea EjercicioRutina para cada ejercicio seleccionado
           g. Crea PlanDia(dia=dia, rutina=rutina)
       → Si no: crea PlanDia(dia=dia, descanso=True)

4.13 VISTA: iniciar_entrenamiento  (views.py)
------------------------------------------------------------------------
Gestiona el flujo de entrenamiento activo.

  → get_or_create Entrenamiento para la rutina actual (completado=False)
  → Obtiene ejercicio_idx del parámetro GET '?ejercicio=N'
  → Si idx >= total ejercicios → redirect a finalizar
  → Carga series existentes del ejercicio actual en este entrenamiento
  → POST action='guardar_serie':
      1. Guarda SerieEntrenamiento con datos del formulario
      2. Si es el último ejercicio → redirect con ?listo=1
  → POST action='siguiente_ejercicio':
      → Redirect con ?ejercicio=N+1
  → POST action='terminar_entrenamiento':
      → Redirect a finalizar_entrenamiento
  → Calcula progreso_pct y peso_total acumulado
  → Pasa mostrar_overlay (True si ?listo=1 y es el último)

4.17 TEMPLATE: entrenamiento_activo.html
------------------------------------------------------------------------

Ejercicios de FUERZA (duracion_minutos es None):
  → Muestra formulario de serie con campos:
       repeticiones, peso, tiempo (opcional), peso corporal (opcional)
  → Botón "Terminar Serie" guarda y recarga
  → Botón "Agregar Serie" permite añadir otra serie al mismo ejercicio
  → Botón "Siguiente" avanza al próximo ejercicio

Ejercicios de CARDIO (duracion_minutos tiene valor):
  → Muestra bloque de temporizador con anillo SVG circular
  → Anillo: radio=70, circunferencia=439.82px
             se calcula stroke-dashoffset según tiempo restante
  → Controles:
       Iniciar/Pausar (toggle)
       Reset (vuelve al tiempo original)
  → Selector de intensidad:
       ½ tiempo → TOTAL_SEG * 0.5
       1× (completo) → TOTAL_SEG * 1
       +50% → TOTAL_SEG * 1.5
  → Al terminar: cambia anillo a verde, vibra el móvil (navigator.vibrate)
  → Formulario oculto auto-rellena tiempo_minutos antes de submitear
  → Si ya se completó el cardio: muestra badge verde de completado

Top Bar (barra superior fija):
  → Timer EN VIVO: contador de segundos desde que cargó la página
  → Contador N/Total ejercicios
  → Porcentaje de progreso

6.1 MODELO: CalculoCaloria  (models.py)
------------------------------------------------------------------------
Guarda los resultados de la calculadora de calorías.

Campos:
  usuario         → ForeignKey a User (nullable)
  nombre          → Nombre de la dieta
  activa          → Boolean (solo una activa a la vez)
  genero          → M | F
  edad, peso, altura, nivel_actividad, objetivo → datos del cálculo
  tmb             → Tasa Metabólica Basal (Mifflin-St Jeor)
  getd            → Gasto Energético Total Diario
  proteinas_g, carbos_g, grasas_g → macros calculados

Método calcular():
  → Fórmula Mifflin-St Jeor:
       Hombre: TMB = 10*peso + 6.25*altura - 5*edad + 5
       Mujer:  TMB = 10*peso + 6.25*altura - 5*edad - 161
  → GETD = TMB * factor_actividad + ajuste_objetivo
  → Macros: proteínas 30% | carbos 40% | grasas 30% (en calorías)
  → Convierte kcal a gramos: proteínas /4, carbos /4, grasas /9

Factores de actividad:
  sedentario: 1.2  |  poca: 1.375  |  activo: 1.55
  diario: 1.725    |  atleta: 1.9

Ajustes de objetivo (kcal):
  perder_rapido: -1000  |  perder: -500  |  mantener: 0
  ganar: +500           |  ganar_rapido: +1000

6.4 VISTA: plan_nutricional  (views.py)
------------------------------------------------------------------------

  Paso a paso (GET):
    1. Obtiene UserProfile del usuario
    2. Construye lista de alertas desde sus limitaciones
    3. Pre-rellena el formulario con datos del perfil:
         genero → M/F si está definido
         edad, peso, altura → si existen
         objetivo → mapeo de objetivo_perfil a objetivo_plan:
           bajar_peso → perder | mantener_peso → mantener | etc.
    4. Renderiza con form, alertas, limitaciones y perfil en contexto

  Paso a paso (POST):
    1. Recibe datos del formulario JavaScript (no del form Django)
    2. Calcula TMB con Mifflin-St Jeor
    3. GETD = TMB * 1.55 (actividad moderada por defecto)
    4. Ajuste según objetivo: perder -15% | mantener 0% | ganar +10%
    5. Distribución de macros:
         Normal:   prot 30% | carb 45% | gras 25%
         Ganar:    prot 30% | carb 50% | gras 20%
         Perder:   prot 35% | carb 40% | gras 25%
         Diabetes: prot 35% | carb 35% | gras 30% (menos carbos)
    6. Ajuste por lesiones (+ 5% proteína para recuperación):
         Si tiene lesion_muscular/rodilla/espalda/hombro:
           prot_pct += 0.05 (máx 40%)
           carb_pct -= 0.05 (mín 30%)
    7. Llama a _build_plan() para generar el plan de comidas
    8. Renderiza con el resultado

6.5 FUNCIÓN: _build_plan  (views.py)
------------------------------------------------------------------------
Genera la estructura de comidas del plan nutricional.

Parámetros:
  calorias_dia, proteinas_g, carbos_g, grasas_g → totales diarios
  comidas_dia  → 3, 4, 5 o 6 comidas
  restriccion  → ninguna|vegetariano|vegano|sin_gluten|sin_lactosa

NOMBRES_COMIDAS y PORCIONES_COMIDA:
  3 comidas: Desayuno 30% | Almuerzo 40% | Cena 30%
  4 comidas: + Media Mañana 15%, reduce proporciones
  5 comidas: + Merienda 15%
  6 comidas: + Pre-Entreno 10%

ALIMENTOS (diccionario por restricción):
  Proteínas → según restricción: pollo/atún/salmón, tofu, tempeh, etc.
  Carbohidratos → arroz, avena, quinoa, papa, etc.
  Grasas → aguacate, aceite oliva, almendras, etc.
  Verduras → brócoli, espinaca, zanahoria, pepino, tomate, lechuga

Para cada comida:
  1. Calcula kcal, proteínas, carbos, grasas según porción
  2. Selecciona el alimento rotando por índice
  3. Calcula la cantidad en gramos según el contenido nutricional
  4. Retorna lista de objetos comida con nombre, emoji, macros y alimentos

9.2 FLUJO: Entrenamiento activo
------------------------------------------------------------------------

   a. Si es FUERZA: formulario de serie
      → Ingresa reps y peso → POST action='guardar_serie'
      → Se crea SerieEntrenamiento
      → Puede agregar más series o avanzar al siguiente
   b. Si es CARDIO: temporizador visual

      → Puede pausar, resetear o cambiar intensidad
